# Photochem v1.0 roadmap

The goal for v1.0 is a stable and well-documented photochemical modeling package with:

- A directly usable rocky-planet `EvoAtmosphere` model.
- A focused `EvoAtmosphereGasGiant` extension that uses the shared core integration and initialization machinery.
- A Python photochemistry-climate coupler for rocky planets that performs fixed-point iteration between `EvoAtmosphere` and `AdiabatClimate`.
- Stable packaging and public Python APIs for Photochem, Clima, and Equilibrate.
- An MkDocs website with API documentation and tutorials for all three components.

Sections 2, 3, 5, 8, and 9 are the main release-blocking phases. Section 4 contains valuable but largely independent condensation improvements that do not automatically block v1.0. Sections 6 and 7 contain later or optional work whose release scope can be decided after the core architecture is in place.

## 1. Completed groundwork

- [x] **1.1 Review and simplify input parsing.** Read through `src/input/photochem_input_read.f90` and simplify code where useful without changing established behavior.

- [x] **1.2 Support charged species in reaction equations.** Fix reaction and species parsing so names can contain plus and minus signs, such as `H+` and `H-`, while rejecting malformed equations with useful errors.

- [x] **1.3 Validate particle optical inputs and interpolation.** Review `interp2particlexsdata`, retain its robust interpolation behavior, and validate particle radius, single-scattering albedo, extinction efficiency, and asymmetry data.

- [x] **1.4 Remove the obsolete evolving-climate mode.** Remove the old self-consistent climate RHS, state, parser options, wrappers, and tests while retaining ordinary fixed-temperature evolution and the separate Clima dependency.

- [x] **1.5 Remove special H2O treatment.** Remove the obsolete fixed-tropospheric-water and water-condensation modes while retaining general aerosol condensation and gas rainout.

- [x] **1.6 Implement persistent pressure-based T-Kzz profiles with finite-rate condensation.** Map prescribed T(P)-Kzz(P) profiles from the current RHS composition during every atmospheric preparation. Keep `set_press_temp_edd` as a one-shot operation, preserve profiles across vertical-grid updates, and integrate the feature into the gas-giant workflow.

- [x] **1.7 Reorganize the test executables by purpose.** Separate focused API correctness tests, broad Valgrind execution, input parsing tests, longer manual evolution tests, and Python wrapper smoke tests; document the testing philosophy and update CI.

## 2. Atmospheric initialization and model lifecycle — required for v1.0

- [x] **2.1 Split static setup from atmosphere-dependent setup internally.** Static setup should read the mechanism, settings, stellar spectrum, and raw optical data and allocate structures whose sizes depend only on the mechanism and `number-of-layers`. Grid construction, gravity, T and Kzz, composition, particle radii, temperature-dependent cross sections and thermodynamics, tropopause validation, working-array preparation, and the initial RHS state should move into the atmosphere-initialization phase. Preserve the current constructor behavior during this internal refactor.

- [x] **2.2 Add explicit initialization state and method guards.** Allow a configured model to exist with `atmosphere_initialized = false`. Static model information and configuration should remain accessible, while integration, RHS evaluation, atmospheric diagnostics, output, and grid updates should return a clear error until initialization succeeds. Initialization and reinitialization should destroy active CVODE state and commit atomically.

- [x] **2.3 Implement altitude-based initialization.** Add `initialize_atmosphere_z`, accepting altitude, temperature, Kzz, gas composition, and optional particle abundances and radii. Validate dimensions, values, species names, composition conventions, and monotonic altitude; map arbitrary input coordinates onto the model grid; set `usol_init` and the working state; and prepare all derived quantities. Reimplement legacy `atmosphere.txt` loading through this common path where practical.

- [x] **2.4 Implement pressure-based initialization.** Add `initialize_atmosphere_p`, accepting pressure, temperature, Kzz, evolved-species composition, and optional particle information. Require a strictly decreasing pressure profile whose first and last points define the lower and upper boundaries of the model domain; interpret the configured planet radius as the radius at the lower boundary. Construct altitude hydrostatically using gas composition only, map all profiles onto the altitude grid, and optionally retain T and Kzz as persistent functions of pressure while allowing composition to evolve normally. Move the general profile mapping and atmosphere-construction work from the gas-giant and `utils.py` `initialize_to_PT` routines into this shared API, while leaving reference-radius conversion, equilibrium chemistry, quenching, boundary-condition policy, and other gas-giant decisions in `EvoAtmosphereGasGiant`.

- [x] **2.5 Make the initial-atmosphere file optional in the public constructor.** Support `EvoAtmosphere(mechanism, settings, flux, data_dir=...)` followed by an explicit initializer. Retain the constructor-with-atmosphere form as a compatibility convenience that immediately invokes file initialization. Remove fake temporary-atmosphere files from extension code.

- [x] **2.6 Simplify atmosphere-grid settings.** Prefer `atmosphere-grid: {number-of-layers: ...}`. Fix the model bottom at zero and determine the top during initialization, removing `bottom`, numerical `top`, and `top: atmospherefile` if the implementation audit confirms they are unnecessary. Move validation requiring the completed grid, such as tropopause placement, into initialization.

- [x] **2.7 Add lifecycle and compatibility tests.** Cover construction without an atmosphere, guarded pre-initialization methods, z- and P-based initialization, reinitialization, failed initialization without partial mutation, legacy file initialization, and gas-giant initialization without a temporary file.

## 3. Shared robust integration and TOA maintenance — required for v1.0

- [ ] **3.1 Correct and centralize robust CVODE restart behavior.** Fix error recovery so an unsuccessful `step` cannot use an undefined time value. Consolidate density clipping, error counting, scheduled restarts, and CVODE reinitialization into a clear shared path while retaining the useful restart after approximately 1,000 steps.

- [ ] **3.2 Audit and harden `update_vertical_grid`.** Verify the altitude- and pressure-based regridding paths for correctness, conservation, failure atomicity, and compatibility with persistent pressure profiles. Replace the scalar MINPACK TOA-pressure solve with a bracketed method such as Brent's method if pressure is reliably monotonic with model-top altitude. Construct and expand a physically valid bracket, reject nonfinite or nonpositive targets, avoid mutating model state until the complete regrid succeeds, and add focused tests for raising and lowering the TOA, endpoint behavior, failed bracketing, and repeated regrids.

- [ ] **3.3 Add optional approximate TOA-pressure maintenance.** Allow the Fortran robust stepper to maintain a configured TOA pressure by occasionally calling `update_vertical_grid` before a scheduled CVODE restart. Regrid only after meaningful pressure drift, and require both chemical convergence and acceptable TOA pressure when the mode is enabled. Keep this opt-in because not every model should be periodically regridded.

- [ ] **3.4 Move gas giants onto the shared robust stepper.** Remove the duplicated Python `initialize_robust_stepper`, `robust_step`, and `find_steady_state` policy and associated counters from `EvoAtmosphereGasGiant`. Configure persistent P-T-Kzz profiles, TOA maintenance, convergence settings, and gas-giant boundary conditions around the common Fortran implementation.

- [ ] **3.5 Verify rocky and gas-giant behavior.** Add focused tests for error recovery, scheduled restart, optional TOA adjustment, and convergence gating. Exercise representative rocky and gas-giant runs and check that the shared implementation does not introduce convergence or performance regressions.

## 4. Condensation and equilibrium partitioning — independent physics development

- [x] **4.1 Support finite-rate condensation with altitude-based T-Kzz profiles.** This is the established baseline with separate gas and aerosol ODE variables.

- [x] **4.2 Support finite-rate condensation with persistent pressure-based T-Kzz profiles.** Diagnose T and Kzz from pressure during every RHS evaluation while retaining the existing finite-rate gas-aerosol transfer.

- [ ] **4.3 Simplify finite-rate condensation and evaporation.** For each gas-particle pair, define `n_eq = RHc*n_sat`, `n_total = n_gas + n_aerosol`, and `n_gas_target = min(n_total, n_eq)`, then transfer material at `J = lambda*(n_gas - n_gas_target)` with equal and opposite tendencies. Use a modest local relaxation rate, such as one based on `Kzz/H**2`, instead of the current RH branches, reciprocal RH, and arctangent damping. Preserve material and assess stiffness and supersaturation under rapid chemical production.

- [ ] **4.4 Implement algebraic equilibrium partitioning with altitude-based profiles.** Integrate one total-condensable variable and diagnose gas and aerosol reservoirs algebraically during every RHS evaluation. Map between the reduced CVODE state and the full public species state, and update the Jacobian, boundary conditions, regridding, restart/output behavior, and diagnostics. Algebraic equilibrium inherently includes evaporation; condensation-only behavior would require a separate history-dependent formulation.

- [ ] **4.5 Combine algebraic partitioning with persistent pressure-based profiles.** Diagnose partitioning and pressure-temperature structure consistently from each CVODE trial state. Use a deterministic active-set or converged fixed-point procedure if the saturation-temperature-composition coupling requires it. Begin with gas-only hydrostatics and assess whether approximate Jacobian treatment is sufficient.

- [ ] **4.6 Test the four-mode compatibility matrix.** Add focused coverage for finite-rate plus altitude profiles, finite-rate plus pressure profiles, algebraic plus altitude profiles, and algebraic plus pressure profiles.

## 5. Rocky-planet photochemistry-climate coupling — required for v1.0

- [ ] **5.1 Design a Python coupling class using composition.** Create a class that owns an `EvoAtmosphere` and an `AdiabatClimate` rather than inheriting from either. Keep chemical integration and climate solution as independently usable components.

- [ ] **5.2 Implement pressure-grid state exchange.** Map photochemical composition onto the climate grid and return updated climate T(P) and Kzz(P), where applicable, through the persistent pressure-profile API.

- [ ] **5.3 Implement fixed-point iteration.** Alternate photochemical integration and climate solves, restarting CVODE after accepted climate updates. Support under-relaxation or another simple stabilization strategy to prevent oscillatory iterations.

- [ ] **5.4 Define coupled convergence and failure handling.** Require both photochemical convergence and sufficiently small changes in climate/composition. Handle failed climate solves, stalled chemistry, iteration limits, and useful progress reporting without hiding errors.

- [ ] **5.5 Add a focused coupled test and rocky-planet example.** Include at least one tractable coupled calculation suitable for regression testing and one scientifically useful tutorial-scale example.

## 6. Model-state checkpoints — after initialization refactor; v1.0 scope to be decided

- [ ] **6.1 Define atmosphere exports versus checkpoints.** Keep `out2atmosphere_txt` as a human-readable atmosphere export and approximate warm start rather than promising complete state restoration.

- [ ] **6.2 Design a versioned full-precision checkpoint format.** Prefer a machine-readable format such as HDF5. Store number densities, grid state, T and Kzz, particle radii, persistent pressure-profile inputs, mutable boundary conditions, and other behavior-affecting state. Exact serialization of CVODE internals is not required.

- [ ] **6.3 Implement and test checkpoint save/load.** Reconstruct a compatible model with fresh CVODE history and verify that a saved steady state and its subsequent behavior are restored within numerical tolerance. Consider coupled-model checkpointing after the base format is stable.

## 7. Optional scientific features and deferred cleanup — not v1.0 blockers

- [ ] **7.1 Consider adding suspended particle mass to hydrostatics.** If condensate loading becomes dynamically important, consider using gas plus particle mass density in hydrostatic column weight while retaining gas number density in `P = n_gas*k_boltz*T`. Revisit this after pressure profiles and algebraic partitioning are mature.

- [ ] **7.2 Consider composition-dependent custom rate functions.** Extend `set_rate_function` so callbacks can depend on species number densities, for example `rate = n_CO2*k`. The Jacobian would need finite-difference or other derivatives of the callback.

- [ ] **7.3 Reconsider legacy conservative TOA adjustment in `evolve`.** Decide whether to retain or remove `rebin_update_vertical_grid`, `rebin_densities`, `update_vertical_grid_file`, and `regrid_prep_atmosphere` after the new initialization and robust TOA-maintenance paths are established.

- [ ] **7.4 Consider a larger CVODE wrapper refactor.** Revisit whether a simpler internal abstraction over the CVODE Fortran interface would materially improve maintainability. Do not undertake this solely for cleanup while the targeted integration code remains reliable.

- [ ] **7.5 Investigate alternative stiff steady-state solvers.** Build a reproducible benchmark set containing models where CVODE stalls or oscillates. First test order-one CVODE and restart strategies, then prototype a linearly implicit Euler pseudo-transient-continuation method using the existing RHS, Jacobian, and banded linear algebra. Use scaled residual reduction, positivity-preserving backtracking, and adaptive pseudo-timesteps. Compare robustness, conservation, convergence, and computational cost against CVODE. Consider a Rosenbrock method such as ROS2 afterward, particularly if accurate transient integration is also needed. Promote an alternative solver to the public API only if it demonstrates a repeatable practical advantage.

- [ ] **7.6 Investigate block-tridiagonal Jacobian linear algebra.** Photochem's layer-major state ordering gives dense local chemistry blocks coupled by transport only to the same species in adjacent layers, so the approximate Jacobian currently supplied to CVODE is block tridiagonal with diagonal off-layer blocks. Verify that this structure remains valid for every boundary condition, particle process, rainout treatment, and persistent pressure profile. Prototype a pivoted block-Thomas solver that assembles the per-layer diagonal blocks and species-diagonal upper and lower couplings directly, and investigate integrating it with CVODE through a custom `SUNLinearSolver`. Benchmark correctness, conditioning, memory, factorization time, total integration time, and convergence against the existing band solver and, if practical, a SUNDIALS sparse/KLU path on representative rocky and gas-giant models. Retain the band solver as a fallback unless the structured solver demonstrates a repeatable advantage. Reuse the structured linear algebra in future pseudo-transient or Rosenbrock experiments if useful.

- [ ] **7.7 Reconsider the default particle radius.** Inventory all implicit particle-radius defaults and assess whether they should be standardized at 1 micron (`1.0e-4` cm) instead of the legacy 0.1 micron (`1.0e-5` cm). Evaluate the consequences for sedimentation, optical properties, and condensation rates; document the selected convention; consider warning when radii are omitted; and provide a migration note if the legacy default changes.

- [ ] **7.8 Simplify gas-giant hydrostatic preprocessing.** Retain the hydrostatic radius estimate needed to evaluate gravity at quench levels and convert the radius specified at `P_ref` to the radius at the photochemical lower boundary, but investigate replacing `compute_altitude_of_PT`, its `solve_ivp` calls, and the `TempPressMubar` callback machinery with a direct trapezoidal integration of `d(1/r)/dln(P) = N_A*k_B*T/(G*M*mubar)`. Recompute the profile after applying quenched composition as currently required, and verify agreement with the existing implementation before removing it.

# Photochem v1.0 roadmap

The goal for v1.0 is a stable and well-documented photochemical modeling package with:

- A directly usable rocky-planet `EvoAtmosphere` model.
- A focused `EvoAtmosphereGasGiant` extension that uses the shared core integration and initialization machinery.
- Stable packaging and public Python APIs for Photochem, Clima, and Equilibrate.
- An MkDocs website with API documentation and tutorials for all three components.

The remaining release-blocking work is the unfinished portion of section 8 and all of section 9. Sections 4 through 7 contain completed experiments, independent scientific development, or deferred features that do not block v1.0. In particular, rocky-planet photochemistry-climate coupling and trajectory/checkpoint work are explicitly deferred until after v1.0.

## 4. Condensation and equilibrium partitioning — independent physics development

- [x] **4.1 Support finite-rate condensation with altitude-based T-Kzz profiles.** This is the established baseline with separate gas and aerosol ODE variables.

- [x] **4.2 Support finite-rate condensation with persistent pressure-based T-Kzz profiles.** Diagnose T and Kzz from pressure during every RHS evaluation while retaining the existing finite-rate gas-aerosol transfer.

- [x] **4.3 Investigate simplifying finite-rate condensation and evaporation — completed; proposed relaxation rejected.** An experiment replaced the existing scheme with conservative local partition relaxation using `n_eq = RHc*n_sat`, `n_total = n_gas + n_aerosol`, `n_gas_target = min(n_total, n_eq)`, and equal-and-opposite transfer `J = lambda*(n_gas - n_gas_target)`. Modern Earth tests exposed an unfavorable saturation-versus-stiffness tradeoff. With `lambda = Kzz/H**2`, the model reached the existing integration-time convergence criterion but required 2,022 accepted steps and about 119 seconds, while maximum active H2O and H2SO4 saturation ratios rose to approximately 108 and 741. Increasing the rate by factors of 10 or 100 did not finish within a five-minute test limit; the factor-10 case remained prohibitively slow even when warm-started from the converged factor-1 state. The established damped scheme completed the reference case in 374 steps and about 10 seconds, with corresponding saturation ratios of approximately 1.15 and 45.5.

  The existing RH-dependent arctangent damping and separate condensation and evaporation timescales therefore provide useful numerical regularization despite their heuristic complexity. Retain the current finite-rate behavior for v1.0 rather than replacing it with another simple relaxation law. The meaningful long-term solution is algebraic gas-aerosol partitioning, which removes the fast exchange mode instead of tuning it; defer that larger development to after v1.0.

- [ ] **4.4 Implement algebraic equilibrium partitioning with altitude-based profiles.** Integrate one total-condensable variable and diagnose gas and aerosol reservoirs algebraically during every RHS evaluation. Map between the reduced CVODE state and the full public species state, and update the Jacobian, boundary conditions, regridding, restart/output behavior, and diagnostics. Algebraic equilibrium inherently includes evaporation; condensation-only behavior would require a separate history-dependent formulation.

- [ ] **4.5 Combine algebraic partitioning with persistent pressure-based profiles.** Diagnose partitioning and pressure-temperature structure consistently from each CVODE trial state. Use a deterministic active-set or converged fixed-point procedure if the saturation-temperature-composition coupling requires it. Begin with gas-only hydrostatics and assess whether approximate Jacobian treatment is sufficient.

- [ ] **4.6 Test the four-mode compatibility matrix.** Add focused coverage for finite-rate plus altitude profiles, finite-rate plus pressure profiles, algebraic plus altitude profiles, and algebraic plus pressure profiles.

- [ ] **7.1 Consider adding suspended particle mass to hydrostatics.** If condensate loading becomes dynamically important, consider using gas plus particle mass density in hydrostatic column weight while retaining gas number density in `P = n_gas*k_boltz*T`. - [ ] **7.2 Consider composition-dependent custom rate functions.** Extend `set_rate_function` so callbacks can depend on species number densities, for example `rate = n_CO2*k`. The Jacobian would need finite-difference or other derivatives of the callback.

- [x] **7.3 Remove legacy moving-TOA adjustment from `evolve`.** Make `evolve` a fixed-grid trajectory integrator. Remove its root-based TOA adjustment, `P_top_min`, `P_top_max`, `top_atmos_adjust_frac`, and the legacy rebin/regrid helpers. Use explicit `update_vertical_grid` or robust-stepper TOA maintenance for supported grid changes, and define restart behavior for fixed-grid trajectories.

  Completed with fixed-grid `evolve` integration, explicit saved-grid validation for `restart_from_file`, removal of the legacy rebin/regrid routines, and removal of their Fortran/Cython public bindings. Focused tests cover a short fixed-grid trajectory and rejection of a restart file whose saved grid does not match the initialized grid.

- [ ] **7.4 Consider a larger CVODE wrapper refactor.** Revisit whether a simpler internal abstraction over the CVODE Fortran interface would materially improve maintainability. Do not undertake this solely for cleanup while the targeted integration code remains reliable.

- [ ] **7.5 Investigate alternative stiff steady-state solvers.** Build a reproducible benchmark set containing models where CVODE stalls or oscillates. First test order-one CVODE and restart strategies, then prototype a linearly implicit Euler pseudo-transient-continuation method using the existing RHS, Jacobian, and banded linear algebra. Use scaled residual reduction, positivity-preserving backtracking, and adaptive pseudo-timesteps. Compare robustness, conservation, convergence, and computational cost against CVODE. Consider a Rosenbrock method such as ROS2 afterward, particularly if accurate transient integration is also needed. Promote an alternative solver to the public API only if it demonstrates a repeatable practical advantage.

- [x] **7.6 Investigate block-tridiagonal Jacobian linear algebra — completed and deferred.** An experimental pivoted block-Thomas `SUNLinearSolver` confirmed that Photochem's Jacobian has the expected block-tridiagonal structure and produced solutions consistent with the existing band solver. It did not demonstrate a compelling end-to-end speedup: a shorter benchmark was approximately neutral (10.31 s band versus 10.06 s block Thomas), while a longer benchmark was slower (11.58 s versus 14.38 s) because the block solver followed a less favorable CVODE trajectory with more steps, RHS evaluations, linear setups, and error-test failures. The large speedups reported for JAX-VULCAN do not transfer directly because its legacy baseline repeatedly factorized the same matrix in SciPy and incurred Python and matrix-repacking overhead, whereas Photochem already uses compiled Fortran/C, CVODE factorization reuse, and relatively few Jacobian evaluations. A direct block-structured Jacobian assembly could reduce the prototype's copying and band-storage overhead, but this is low priority and not a v1.0 goal. Revisit only if future profiling shows that linear setup and solves dominate important workloads, or if structured linear algebra becomes useful for a future pseudo-transient or Rosenbrock solver.

- [ ] **7.7 Reconsider the default particle radius.** Inventory all implicit particle-radius defaults and assess whether they should be standardized at 1 micron (`1.0e-4` cm) instead of the legacy 0.1 micron (`1.0e-5` cm). Evaluate the consequences for sedimentation, optical properties, and condensation rates; document the selected convention; consider warning when radii are omitted; and provide a migration note if the legacy default changes.

- [ ] **7.8 Simplify gas-giant hydrostatic preprocessing.** Retain the hydrostatic radius estimate needed to evaluate gravity at quench levels and convert the radius specified at `P_ref` to the radius at the photochemical lower boundary, but investigate replacing `compute_altitude_of_PT`, its `solve_ivp` calls, and the `TempPressMubar` callback machinery with a direct trapezoidal integration of `d(1/r)/dln(P) = N_A*k_B*T/(G*M*mubar)`. Recompute the profile after applying quenched composition as currently required, and verify agreement with the existing implementation before removing it.

- [x] **7.9 Experiment with an analytical chemistry Jacobian — successful and adopted for v1.0 in 8.9.** The `experiment/analytical-chemistry-jacobian` branch demonstrated a working stoichiometry-driven analytical chemistry Jacobian and focused Fortran tests. It directly accumulates reaction derivatives using leave-one-reactant-out products and covers particle-density mappings, algebraically eliminated short-lived species (`n_sl = P/L`), gas rainout, and piecewise finite-rate condensation and evaporation. The implementation avoids a redundant `dochem` call and does not compute or return an unused RHS. Autodiff remains available as an explicitly selectable independent correctness oracle. The analytical and autodiff Jacobians agreed in the focused tests, including combined particle, short-lived-species, and rainout cases, and the analytical path completed the Modern Earth integration successfully.

  The experiment produced a useful but bounded speedup. In one Modern Earth timing, the analytical path took about 8.52 s and 345 accepted steps, compared with about 11.15 s and 374 accepted steps for autodiff. Instruments showed why the opportunity is limited: approximately 0.37 s of an 8.87 s sampled run was spent in the Jacobian callback (about 4%), while band factorization and solves consumed about 4.67 s (about 53%) and the RHS about 2.82 s (about 32%). The analytical path was roughly comparable to the finite-difference path in end-to-end runtime, but its direct derivatives, numerical behavior, and improvement over autodiff make it worth adopting for v1.0. Linear solves remain the larger performance bottleneck.

  Production adoption was completed in 8.9. Profiling suggests that future performance work beyond this should prioritize the linear solve. SUNDIALS 5.7 can be configured successfully with the conda environment's OpenBLAS using `ENABLE_LAPACK=ON` and an explicit `LAPACK_LIBRARIES` path, but selecting and benchmarking its LAPACK band solver is separate follow-up work.

- [ ] **7.10 Consider compensated or distilled reaction-rate summation.** Revisit numerical summation only as a targeted response to demonstrated production-loss cancellation that causes inaccurate steady-state residuals or CVODE stalling. Previous K-fold experiments showed little general benefit with the then-default autodiff Jacobian, but helped finite-difference Jacobians when a small perturbation amplified RHS roundoff as `error/h`. After the analytical-Jacobian experiment, measure cancellation using `sum(abs(contributions))/abs(sum(contributions))` at difficult states; first test pairing forward and reverse reaction fluxes and inexpensive Neumaier or Kahan summation, then compare K-fold distillation if necessary. Keep autodiff or high-precision calculations as validation oracles, and benchmark RHS cost, CVODE steps, Jacobian evaluations, convergence, and final states. Do not enable distillation globally unless representative current models show a repeatable robustness or end-to-end performance benefit; this research is optional and does not block v1.0.

- [ ] **7.11 Expose model-wide diagnostics for Chempath integration.** This is separate from the species-focused `production_and_loss` interface and is not required for v1.0. Expose through the Python API all state and rate information needed to construct Chempath inputs, including species densities, actual reaction event rates, rainout, signed transport tendencies, boundary contributions, distributed sources, condensation and evaporation, escape, and custom-rate contributions where applicable. Ensure the diagnostics correspond unambiguously to a freshly prepared model state and do not rely on stale work arrays. Keep Photochem independent of Chempath; implement the conversion as a small Python function that accepts an `EvoAtmosphere` object and constructs the Chempath inputs. Use PR #40 and `codex_reference/chempath-main` as design references and preserve appropriate contributor credit.
